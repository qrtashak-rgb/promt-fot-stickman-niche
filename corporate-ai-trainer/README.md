# Корпоративный ИИ-наставник

Telegram-бот, который изучает документы компании (регламенты, инструкции,
FAQ) и отвечает на вопросы новых сотрудников на их основе, указывая
источник. Если ответа в базе нет — честно об этом говорит, а не выдумывает.

## Как это работает

1. Документы из `knowledge_base/` режутся на фрагменты и превращаются в
   эмбеддинги (модель `sentence-transformers/all-MiniLM-L6-v2`, работает
   локально, бесплатно, без внешнего API).
2. Эмбеддинги хранятся в локальной векторной БД (ChromaDB, папка
   `chroma_db/`).
3. Когда сотрудник задаёт вопрос боту, бот ищет ближайшие по смыслу
   фрагменты и передаёт их вместе с вопросом модели Claude (Anthropic API),
   которая формирует ответ строго на основе этого контекста.
4. Если ни один найденный фрагмент недостаточно близок к вопросу (порог
   `MAX_DISTANCE` в `.env`) — бот не обращается к LLM, а сразу отвечает,
   что информации нет, и советует обратиться к человеку.

## Установка

```bash
cd corporate-ai-trainer
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# впишите в .env:
#   ANTHROPIC_API_KEY   — https://console.anthropic.com
#   TELEGRAM_BOT_TOKEN  — получить у @BotFather в Telegram
#   ADMIN_IDS           — свой Telegram user id (узнать у @userinfobot)
```

## Загрузка базы знаний

1. Удалите `knowledge_base/example.md`.
2. Положите в `knowledge_base/` реальные документы компании: `.txt`, `.md`,
   `.pdf`, `.docx` (можно вложенными папками).
3. Постройте индекс:

```bash
python ingest.py
```

Скрипт выведет, сколько документов и фрагментов проиндексировано.

## Запуск бота

```bash
python bot.py
```

Команды бота:
- `/start` — приветствие и объяснение, как пользоваться.
- `/reload` — переиндексировать базу знаний заново (только для
  администраторов из `ADMIN_IDS`); используйте после обновления документов.
- Любое текстовое сообщение — вопрос, бот отвечает на основе базы знаний.

## Обновление документов

Когда регламенты меняются — замените/добавьте файлы в `knowledge_base/` и
вызовите `/reload` в боте (или заново запустите `python ingest.py`, если
бот не запущен). Полной переиндексации достаточно для проекта такого
масштаба; отдельного механизма diff-обновлений нет.

## Ограничения текущей версии (MVP)

- Нет разграничения доступа по ролям к конкретным документам — все, у кого
  есть ссылка на бота, видят все ответы. Если нужна конфиденциальность —
  добавьте проверку `message.from_user.id` по списку сотрудников или
  фильтрацию документов по метаданным.
- Порог релевантности (`MAX_DISTANCE`) подбирается опытным путём — после
  первых реальных вопросов может понадобиться подстроить значение в `.env`.
- Хранилище (`chroma_db/`) и виртуальное окружение — локальные; для работы
  24/7 бот нужно развернуть на сервере/VPS и держать процесс `python bot.py`
  запущенным (например, через systemd или screen/tmux).
